# 互斥规则实现与历史配置盘点计划

| 版本号 | 日期 | 变更说明 | 作者 |
| :--- | :--- | :--- | :--- |
| v1.0.0 | 2026-10-24 | 按已确认设计实施并只读盘点当前部署数据 | Agent |

**Goal:** 实现任意 host 至多命中一条规则、相同出口交叠拒绝、支持星号且拒绝正则、字母排序与无调序界面，同时交付历史配置风险报告。

**Architecture:** 规则编译器共享有界星号匹配与交集分析；所有写入/加载使用严格校验，运行时不按 position 决胜。后端规范排序并保留快照位置兼容；前端维护完整草稿并派生筛选分页。

**Tech Stack:** Python 3.12 标准库、SQLite、FastAPI 可选 Web、原生 JavaScript。

**Spec:** [DD_RULES §11](../docs/design/DD_RULES.md#11-互斥规则与无优先级匹配目标设计)、[DD_WEB §10.7.1.2](../docs/design/DD_WEB.md#10712-互斥规则页面与写入契约目标设计)。

## Global Constraints

- 保留当前工作区的已有改动；本次不切换分支、不提交、不改写生产配置、不重启容器。
- 规则最多 5,000 条，条件最多 1,000 字符，前端每页最多 100 条；核心无新增第三方依赖。
- 不能把未知交集或校验超预算当通过；不能依赖输入顺序、出口是否相同或抽样判断互斥。
- `*.example.com` 包含主域与所有子域，但不匹配 IP；普通星号可跨点，匹配零字符。
- 历史规则盘点使用 SQLite mode=ro，报告存入本地忽略的 .learnings，不打印认证令牌或代理凭据。

## Review Focus

- 主域特例、数字域名后缀及 IP 规范化必须在运行时与交集检查一致。
- 前端失焦排序与即时校验不能吞掉删除/保存点击、焦点或过滤中的草稿。
- 校验失败不得更新数据库、revision、备份、成功审计及运行快照；固化失败保留粘性。
- 有界分析对 5,000 条常见域名规则仍可用，复杂模式明确失败且不留下无界后台任务。
- 新引擎上线前的历史正则/交叠不得自动删除或改变现有容器路由。
