## 三平台运行审计复核

- 相对库路径从 CWD 解析违反配置契约。显式配置、环境变量、平台默认值统一入口，应用实例固定配置路径。三个库的相对路径按配置目录解析。测试覆盖不同 CWD 下的磁盘读取及 Web 预校验。部署须核对曾依赖旧 CWD 的数据库位置。
- 本机安装的 Uvicorn 源码确认 Windows 监听 SIGBREAK 并在恢复旧处理器后重抛。CLI 增加 SIGBREAK，模拟测试确认请求停止和恢复处理器。Windows SCM 的停止控制由服务包装器处理，不能从 SCM 的控制消息推导固定的子进程终止方式。
- CPython 3.12 默认 stderr 在 cp1252 下将不可编码字符转义。stdout 重定向及自定义严格流可出现编码异常。Windows CLI 在解析命令行前把可重配标准流切至 UTF-8。测试用真实重定向文件验证输出。
- 快速重启建议写入部署文档。端口占用错误本身无法区分旧进程、其它进程或残留连接。维持现有绑定语义。
- 模拟 WinError 32 验证原子替换短暂冲突重试成功以及冲突持续时失败、旧字节完整和临时文件清理。
- SQLite 写连接确认实际 WAL 模式。内存 SQLite 用于模拟无法启用 WAL，验证中文提示及连接关闭。成功进入 WAL 无法证明目录不是网络共享。
- WebRunner 返回时服务器可能尚未监听。后台任务等待就绪后记录实际绑定端口，真实回环 Web 启动覆盖 port=0。Windows 原生 SIGBREAK、服务包装器和文件共享冲突仍按发布验收清单核验。

最终验证：1492 项全量测试通过，2 条第三方弃用警告。Ruff、MyPy 和 diff 检查通过。本轮 Windows 专用行为在 Linux 环境用平台模拟验证，原生 Windows 和 macOS 验收待发布时执行。

- NSSM 与 WinSW 的控制台停止及超时配置已按各自官方文档补充。队列和提交状态决定强制终止的损失范围，刷新间隔及批大小不构成上限。
- 1501 项全量测试通过，2 条第三方弃用警告。Ruff、MyPy 和 diff 检查通过。Windows 包装器实际停止流程待原生验收。


## R1–R7 旧库升级保护复核

运行时按三个库汇总冲突。只读检查 schema_meta 和对应业务表，忽略可识别为非项目库的同名文件。候选缺失、为空或缺少项目表时阻断，两个不同的项目库并存则记录 W_LEGACY_DB_PATH 并使用配置目录库。同一文件别名不告警。Web 恢复保留 E_LEGACY_DB_PATH 响应码和详情，失败前没有备份或写盘。离线审计仅复用路径解析，不推断服务 CWD。

异步启动和重载把配置读取及旧库探测放到工作线程。Web 通过异步 getaddrinfo 解析首个 IPv4 数值地址，再预绑定，兼容 localhost。部署说明明确 Web 端口冲突使整个服务退出 2。

回归先复现 R1–R5 的错误，再验证修复。全量测试 1509 项通过，2 条第三方弃用警告。Ruff、MyPy 与 diff 检查通过。
